# AutoStronghold

《明日方舟》「卫戍协议」非官方自动化工具。自动进行「极速模拟」与「独立模拟·规程等级1」，获取策略金标、彩标和蚀刻章。

本项目部分游戏界面行为参考 [GarrisonFarm](https://github.com/UnknownGlyph/GarrisonFarm) 及优化版 [GarrisonFarm-Personal](https://github.com/FJH3576/GarrisonFarm-Personal) 已实现的功能，重新设计架构、独立编写代码，不包含原项目的源代码文件、bat 或二进制内容。部分游戏界面坐标（如商店卡位、出售区、拖拽停放点）与少量颜色阈值参考了原项目中的数值，并在实机截图上重新测量核对。`autostronghold/game/rules.py` 移植了 [Stronghold-Protocol](https://github.com/sganggs/Stronghold-Protocol)（GPL-3.0-or-later）的规则代码。许可证为 [GPL-3.0-or-later](LICENSE)，见文末「许可证」。

## 功能

在程序窗口中选择设备和功能：

| 功能 | 做什么 |
| --- | --- |
| 1. 蚀刻章 | 进入「个人模拟 → 极速模拟」，统计已获得角标（金标或彩标）的策略。达到 20 个即结束并提示完成；否则选择第一个没有角标的策略进行模拟，一局结束后重新统计。 |
| 2. 全角标金标 | 先在「极速模拟」中把所有策略刷到有角标（金标或彩标），全部达标后退出，进入「独立模拟」选择「规程等级 1」，把仍没有角标的策略依次刷完，全部达标后结束并提示完成。 |
| 3. 全角标彩标 | 同上，但要求每个策略都是彩标。 |

* 扫描策略列表时，一旦已读到的策略足以判断就停止：蚀刻章数到 20 个角标即结束；全角标功能遇到第一个未达标的策略就直接选择并进入，不再读完整个列表。
* 进入「独立模拟」后检查当前规程等级，不是所需等级时点击或上下滑动难度列表切换；所需等级尚未解锁时停止并说明。
* 选定策略后**不选择自选编队**，直接点击「准备就绪」。
* 开始界面处于「联合模拟」时（显示「同盟模拟」「搜寻队友」），切换至「个人模拟」。
* 出现「道具补给」或「战术决策」时，选择中间选项并点击「确认选择」。
* 准备阶段误点右下角「收起」后，会自动点击「展开」恢复界面。
* 干员只部署在地图**最右侧第 2～4 列（不含红门列）与最上方第 1～3 行**所覆盖的格子里（最多 8 名），全部朝右。
* **每日 4:00 数据更新**后自动返回：对局结算时出现「数据已更新，即将进行同步」时点「√」，关闭「今日配给」、签到与公告弹窗，在游戏主界面点「卫戍协议·规程」回到卫戍协议，「断线重连」上方显示「已终止」（对局被数据更新中断）时点它完成结算，然后照常运行。每一步出现才处理，没出现的跳过。
* 开始界面显示「断线重连」、上方为「当前回合」（有一局尚未结束的对局，不是被数据更新中断）时，程序不会接着打，而是停止并提示：请在游戏中打完或放弃当前对局，回到开始界面后重新运行。
* **60 秒**内未检测到卫戍协议画面（断线、其他弹窗、已离开卫戍协议等）时停止并说明原因；**10 分钟**内对局流程没有推进时同样停止，并保存截图。
* 每局结束后（无论是否通关）释放并重建文字识别与打法，避免长时间运行积累状态；设备连接保持不变。连续 5 局未通关时停止。

## 选择哪个版本

电脑上有两个版本，功能完全相同，只是文字识别（OCR）的运行位置不同；另有直接装在安卓设备上的安卓版：

| 版本 | 适用 | 说明 |
| --- | --- | --- |
| `AutoStronghold-CPU.zip` | 所有电脑 | 不需要显卡。识别只占用少量 CPU 线程。 |
| `AutoStronghold-GPU.zip` | 有支持 DirectX 12 的独立或集成显卡（NVIDIA / AMD / Intel） | 用 DirectML 在显卡上识别，CPU 占用更低、识别更快。**不需要安装 CUDA。** 启动时会检测显卡；检测不到可用显卡时会写明原因，并询问是否改用 CPU 继续。 |
| `AutoStronghold-Android.apk` | 屏幕为 **16:9** 的安卓设备（安卓 8.0 及以上，64 位 ARM），例如 1920×1080 的平板 | 装在运行游戏的设备上，不需要电脑。用录屏截图、用无障碍服务点击和拖动，文字识别在本机 CPU 上运行。功能与电脑版相同。 |

拿不准就用 CPU 版。GPU 版启动时提示「未检测到可用的显卡」或「显卡驱动不支持 DirectX 12 / DirectML」时，请更新显卡驱动或改用 CPU 版。

## 运行前的准备

1. **游戏设置**：客户端为国服中文版，卫戍协议「更换主题」为默认主题。
2. **分辨率**：16:9，推荐 **1920×1080**。其他 16:9 分辨率按比例换算，测试较少。
3. **模拟器**：把显示分辨率调成 1920×1080（测试环境为 MuMu 模拟器 12），并开启模拟器的「ADB 调试」选项。程序自动查找正在运行的模拟器（MuMu、雷电、蓝叠、夜神等），找到多个时由用户选择。
4. **PC 端（鹰角启动器）**：
   * 游戏分辨率设为 1920×1080，窗口化或全屏都行；窗口不要最小化（可以被其他窗口挡住）；
   * **游戏内界面缩放设为 100%**。程序在卫戍协议开始界面检测该设置，不是 100% 时给出提醒；
   * **PC 端运行时程序通过鼠标点击和拖动，会占用鼠标**，请注意；
   * 游戏以管理员权限运行，所以本程序操作 PC 端时也需要管理员权限：选择 PC 客户端并点「开始」（或「连接自检」）时弹出 UAC 确认，点「是」后程序以管理员身份重新打开并继续；使用模拟器时不需要；
   * 游戏公告是单独的窗口，请先手动关闭。
5. **安卓版**：
   * 屏幕必须是 16:9。20:9 等比例的手机上游戏界面布局不同，程序无法使用；
   * 首次使用时在系统设置中开启无障碍服务「AutoStronghold 触控」（只执行点击和拖动，不读取界面内容）。安卓 13 起，从安装包安装的应用需先在「应用信息 → 右上角菜单」中「允许受限制的设置」，开关才能打开；
   * 每次点「开始」都要允许「录制或投射屏幕」，请选择「整个屏幕」。之后程序自动切换到明日方舟（官服或 B 服），在通知栏可以随时「停止」。
6. 进入游戏的「卫戍协议」开始界面（右下角显示「个人模拟」/「联合模拟」）。
7. 运行期间不要操作游戏画面，也不要同时运行 MAA 等其他自动化程序。

## 使用

1. 解压发布包（不要在压缩包里直接运行）。发布包里只有 exe 和 `_internal` 文件夹；许可证文本在 `_internal\licenses`。
2. 双击 `AutoStronghold-CPU.exe`（GPU 版为 `AutoStronghold-GPU.exe`），打开图形界面：
   * 左侧选择**设备**（模拟器 / PC 客户端）和**功能**（蚀刻章 / 全角标金标 / 全角标彩标）；选项中可设置最多进行几局（0 为不限）、全角标功能直接从「独立模拟·规程等级1」开始，GPU 版还可选择不使用显卡（改用 CPU 识别）；
   * 点「连接自检」只检查连接和识别，点「开始」开始运行，运行中同一按钮变为「停止」；
   * 右侧显示运行状态（当前画面、阶段、回合、对局与通关数、运行时长）和日志；右上角「运行前须知」是运行前的准备说明；
   * 上次的选择会自动记住。

运行日志和出错时的截图保存在程序目录下的 `logs` 文件夹。

**安卓版**：安装 `AutoStronghold-Android.apk` 后打开 AutoStronghold，界面与电脑版相同（设备固定为本机）。日志与截图在 `Android/data/com.autostronghold.app/files/logs`；要调整打法时，把 `tactics/` 或 `layout/` 文件夹放到 `Android/data/com.autostronghold.app/files/` 下。

## 调整打法与站位

每种模拟有各自独立的打法（卫戍协议·规程 序列Ⅰ，SP3），按模式和规程等级自动选择：

| 模拟 | 打法 | 参数文件 |
| --- | --- | --- |
| 极速模拟 | SP3·极速模拟 | `tactics/sp3_fast.json` |
| 独立模拟·规程等级1 | SP3·独立模拟·规程等级1 | `tactics/sp3_independent_l1.json` |
| 独立模拟·规程等级2～20（现有功能不使用，见「已知限制」） | SP3·独立模拟·通关优先 | `tactics/sp3_independent_clear.json`（按 2～4、5～8、9～14、15～20 分组） |

参数默认打包在程序内。需要调整时，把仓库 `resources/` 下的 `tactics/` 或 `layout/` 文件夹复制到 exe 旁边再修改，重新运行即生效（exe 旁边的文件优先）；`layout/board.json` 是地图格子坐标与可部署区域。旧打法「叠层优先」（`tactics/default.json`）保留在程序中作对照，默认不再使用。

干员表与参数文件都标有适用的赛季版本（`act3autochess@V3_1`），干员表另有内容哈希；版本不符、文件缺失或干员表被改动时，该模拟改用旧打法「叠层优先」并在日志中说明原因。日志逐条记录每个动作针对的干员（SP3 数据 ID、识别置信度）、商店栏位或格子与评分，并在每回合末汇总动作次数。

三种打法共用同一套规则框架，各自的数值独立：

* **识别干员**：按卡名查 SP3 干员表（`resources/data/sp3_operators.json`，141 名干员、26 个盟约），得到阶级、盟约、近战/远程、职业与阻挡数；卡名有 OCR 杂字时取其中唯一的干员名；玩家没有该干员时卡上显示补位干员（预备干员-术师、Sharp、Touch 等），按补位干员的身体决定站位，按卡上的盟约计算盟约；
* **买谁**：比较「买下后场面强度增加多少」——阶级强度（精锐 ×2.2）＋ 盟约达到的门槛（精准、奥术权重最高）＋ 路线上至少 3 名可阻挡的近战；同名副本按合成精锐的价值计算，已有精锐的干员不再买；
* **升级**：按回合计划升级（极速模拟第 2 回合 3 级、第 6 回合满级），升级前先保证场上人数；回合末剩余资金够升级就升级（资金不会保留）。每次只点一下「升级」再核对，没生效才点第二下；读不到「升级」框时按当前商店等级对应的位置点击，以资金是否减少判断；
* **刷新**：达到计划等级后才刷新，每回合有上限；领袖轮先卖掉整备区里用不上的干员（极速模拟），再把资金全部用于购买和刷新；
* **站位**：近战优先放敌人路线格，远程优先放木框高台，全部朝右；场上满 8 人时，明显更强的干员替换收益最低的那名；
* **整备区**：超过 7 名时出售，顺序为 非精锐 > 场上没有同名 > 份数少 > 阶级低；购买时至少留 1 个空位，准备就绪前至少留 2 个；召唤物占格子，但不出售、不部署；在最左格时移到右侧空位（最左格留给最后一名，用来判断整备区已满）。拿不起来、读不出的格子每局最多读两次。

打法的推导与模拟器评测（胜率、用时、种子、失败样例）见工作区 `docs/` 中的「SP3-极速模拟-无模型策略」「SP3-独立模拟-无模型策略」「SP3-无模型策略-证据与评测」。

## 已知限制

* 只支持国服中文客户端、默认主题、16:9 画面；活动或游戏版本更新后地图和界面坐标可能需要重新校准。
* 打法胜率来自模拟器（Stronghold-Protocol 的 SP3 数据）评测，尚未经过大量实机对局验证；连续 5 局未通关会自动停止，避免无效刷取。
* 不识别领袖（右上角只有头像），不购买、不装备装备，不使用冻结和策略主动技能。
* 达标后退出模拟的确认弹窗尚未在实机上验证。
* 「道具补给」与「战术决策」始终选择中间选项，不分析选项内容。
* 「全角标」功能的独立模拟使用「规程等级 1」。程序可以切换到任意已解锁的规程等级，打法也已写好，但目前只开放规程等级 1～4（与 1 同为战场#01）；规程等级 5～20 还有 9～10 张不同地图，目前只有战场#01 的格子坐标。「联合模拟」已预留接口但尚未实现。
* 角标识别依据卡片右上角的图标；遇到识别遗漏时会以策略面板上的「已通过模拟 N 次」为准纠正。
* 达标后需要退出当前模拟：程序会点击左上角退出并确认；若游戏的退出弹窗与预期不同，会停止并提示手动退出（进度不受影响）。
* 安卓版尚未在实机上完整验证；只支持 16:9 屏幕与 64 位 ARM 设备。识别在手机 CPU 上运行，比电脑版慢，每局用时更长。
* PC 端依赖 MaaFramework 的窗口输入（默认 AnchoredTouch，失败时自动尝试其他方式）；部分系统可能需要安装「VC++ 2015-2022 x64 运行库」。
* 杀毒软件可能误报打包的 exe；不支持 32 位系统和 Windows 7/8。

## 从源码运行与构建

需要 Windows 与 Python 3.11。

```powershell
py -3.11 -m venv .venv-cpu
.venv-cpu\Scripts\python -m pip install -r requirements-cpu.txt
.venv-cpu\Scripts\python -m autostronghold                      # 从源码运行

powershell -ExecutionPolicy Bypass -File packaging\build.ps1    # 生成 dist\AutoStronghold-CPU.zip 与 dist\AutoStronghold-GPU.zip
```

构建脚本会自动创建缺少的构建环境（`.venv-cpu`、`.venv-gpu`）。

安卓版：`packaging\build.ps1 -Variant android` 生成 `dist\AutoStronghold-Android.apk`（`-Variant all` 同时生成三个包）。需要 JDK 17 以上与 Android SDK（平台 34）；Gradle 与 Chaquopy 安装依赖用的 Python 3.10 缺少时自动下载到 `build\android`（固定版本，校验 SHA-256）。工程在 `android/`：同一个 `autostronghold` 包运行在 Chaquopy 的 Python 3.10 上，截图（MediaProjection）、触控（无障碍手势）和 ONNX Runtime 推理由 Kotlin 提供；`android/app/src/main/python` 中是 RapidOCR 需要的 `onnxruntime` 与 `pyclipper` 接口的替代实现（两者没有安卓版 Python 包）。
